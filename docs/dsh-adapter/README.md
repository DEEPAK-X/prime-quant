# DSH adapter — three-agent handoff pack

Self-contained plans so three independent agents can add DeepSeek Harness as an
**optional** web surface while keeping Prime Agent as the quant brain and the
existing Vite GUI as the default `prime-agent gui`.

**Do not implement from this README.** Read `01` + `02` + your agent file + `06`.
The product decision and the three-pattern stack live in `01`. The frozen wire
shapes live in `02`. Your milestones live in `03` / `04` / `05`. Integration
after all three land is `06`.

## Documents

| File | Audience | Contents |

## Parallel-work safety

- A develops the provider against a **fake** Prime child (injected spawn). No live DSH, no paid tokens.
- B develops ConversationNodes against **fixture SessionEvent scripts** in `fixtures/`. Does not need DSH or Prime running.
- C spikes `dsh web` on Windows and writes launch/docs against the frozen patch ids. Pattern 3 waits for A Phase 2.
- Nobody runs `npm run dev`, `npm run build`, or `npm test`. Targeted vitest from the package root only, as in `AGENTS.md`.

## Repo rules that apply to you

Read `AGENTS.md` at the repo root before writing code. Non-negotiables:

- `npm run check` must pass before every commit (biome + tsgo, zero warnings)
- Never `git add -A`; stage only files you created or modified
- Never `git reset --hard`, `git checkout .`, `git stash`, or force push
- No `any` types, no inline `import()`; standard top-level imports only
- 7-day minimum release age for new npm dependencies (`.npmrc` enforces it)
- Target platform is **Windows**
- Every child `spawn` / `execFile` passes `windowsHide: true`
- Never spawn `"npx"` on win32 (`.cmd` shim)
- Daemon protocol changes are capability-gated; DSH startup must work with zero Prime processes
